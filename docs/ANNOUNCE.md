# Launch checklist and community outreach

1. Make the repository Public only **after** reviewing code, ZIPs, git history and Actions logs for secrets.
2. Add an accurate description and relevant topics; include one short demo video or GIF recorded on a test account with no private data.
3. Release a reproducible, well-tested APK via GitHub Releases (not a random file host). Label debug builds clearly.
4. Write a short changelog and issue templates, and choose an explicit open-source license if redistribution is intended.
5. Share a demo + explanation with Android developer communities, model/tool-use groups, and bilingual Moroccan tech audiences. Follow each community's self-promotion rules.
6. Ask early testers for Android version, model/provider, and redacted bug reports. Prioritize bug fixes over download count.

Suggested demo: Start at JARVIS home screen, enable the accessibility service, give a harmless task like ‘open Settings and show battery usage’, demonstrate blue cursor/edge feedback, then show Stop and Vision/SC toggle. Record on a demo device with fake accounts.
